01 — How it works

Claude asks the catalog, reads two cards, and gets to work.

  1. A

    Route

    The catalog is too big to read, so Claude searches it with a small script. Cost in context stays the same whether the catalog holds 26 skills or 5,000.

    python3 scripts/route.py "design a landing page for my app"
  2. B

    Load

    Only the winning skill is read, plus one supporting skill when it scores close behind. Everything else stays on the shelf.

  3. C

    Work

    The primary skill sets the process and the quality bar. For long jobs with phases, Claude routes again at each phase.

  4. D

    Rate

    Each answer ends with the skills it used and a link to rate them. Ratings feed the next ranking, for everyone.

02 — Ranking

How a skill wins a task.

score equals relevance × (0.6 + 0.4 × rating ÷ 5)

Relevance comes first. It is a text match between your task and each skill's name, tags and description. A five-star skill for the wrong job never wins.

Ratings break ties between skills that fit. Every skill starts at 3.5, and needs about eight real votes before its own average takes over.

No match, no skill. If nothing in the catalog fits, the router says so and Claude carries on unaided.
