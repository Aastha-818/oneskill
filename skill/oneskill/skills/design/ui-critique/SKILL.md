# Ui Critique

## How to look
Go through the screen three times, each with one question:
1. **Five-second pass** - what is this, and what am I meant to do? Note the first three things the eye lands on. If the primary action is not among them, that is finding number one.
2. **Task pass** - walk the main task step by step. Record every hesitation: unclear label, missing feedback, unexpected jump, dead end, error with no recovery.
3. **Detail pass** - alignment, spacing rhythm, type scale, colour contrast, touch target size (44px minimum), empty, loading and error states.

## What to check
- Hierarchy: one obvious primary action per screen; secondary actions visibly quieter.
- Consistency: same thing looks the same everywhere; different things look different.
- Language: labels say what happens ("Save draft"), not what the system calls it.
- Accessibility: contrast 4.5:1, visible focus, not colour alone, sensible reading order.
- Density: every element earns its place - list what could be removed.

## How to report
Lead with a two-line verdict. Then findings ordered by impact on the user's task, not by where they appear on screen. Each finding: what is wrong, why it costs the user, and a concrete fix. Mark severity (blocks task / slows task / polish). Say what works well so it is not lost in a redesign. Never give more than about ten findings - cut to the ones that matter.
